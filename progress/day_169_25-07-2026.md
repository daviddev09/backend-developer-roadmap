# День 169 (25.07.2026): Введение в Docker Compose
## Теория:
* Зачем нужен Compose: когда у тебя есть приложение, база данных и кэш, запускать их по отдельности длинными командами docker run с кучей флагов неудобно. Compose позволяет описать всю инфраструктуру в одном файле.
* Синтаксис YAML: базовые правила отступов в файлах .yml (строго пробелы, никаких табов).
* Структура docker-compose.yml: блок services (описание каждого контейнера).
* Перенос флагов из консоли в файл: как параметры image, ports и environment заменяют флаги командной строки.
* Управление через Compose: команды docker compose up -d (поднять всё в фоне) и docker compose down (остановить и удалить всё).
## Практика:
* Создай пустую директорию и внутри неё файл docker-compose.yml.
* Опиши внутри сервис web, используя образ nginx и пробросив порт 8080:80.
* Запусти инфраструктуру командой docker compose up -d.
* Проверь работу сервиса в браузере. Посмотри логи командой docker compose logs -f web.
* Останови и полностью удали контейнеры и сеть командой docker compose down.

## Конспект изученных материалов
### 1. Зачем нужен Docker Compose
* Представь, что нужно поднять проект из пяти контейнеров: придется писать пять разных длинных команд, прописать кучу переменных и не забыть пробросить правильные порты. Ошибиться в одной букве очень легко.
* **Compose** позволяет описать всю инфраструктуру проекта в одном файле. В файле один раз описывается все настройки, кладется файл в Git вместе с кодом, и любой разрабтчик сможет запустить весь проект одной короткой командой. Очень удобно.
### 2. Синтаксис YAML
* Файлы Docker Compose пишутся на языке разметки YAML (расширение .yml). Он легко читается человеком, но у него есть одно жесткое правило:
    * Базовые правила отступов в файлах .yml - это пробелы, никаких табов. Если нажать клавишу Tab для создания отступа, парсер YAML выдаст ошибку и ничего не запустится. Нужно использовать ровно два пробела для каждого нового уровня вложенности.
### 3-4. Структура docker-compose.yml и перенос флагов
* Главная структура файла базируется на блоке services (описание каждого контейнера). Каждый сервис - это, по сути, один будущий контейнер. В структуре файла можно заменить флаги: **-p, --name, -e** на понятные названия.
* **Разбор структуры:**
    * **services** - обязательный корневой блок
    * **web-app** - имя сервиса. Compose автоматически использует его для генерации имени контейнера
    * **image: nginx** - заменяет имя образа в конце команды *docker run*
    * **ports:** - список портов (заменяет флаг **-p**). Спереди ставится дефис **-** - в YAML так обозначаются массивы (списки). Строки с портами принято брать в кавычки.
    * **environment:** - список переменных окружения (заменяет флаг **-e**)
### 5. управление через Compose
* Больше не нужно запоминать сложные команды запуска контейнера. **Управление через Compose** сводится к командам *docker compose up -d* (поднять всё в фоне) и *docker compose down* (остановить и удалить всё).
    * *docker compose up -d* - Docker сам прочитает файл .yml, скачает нужные образы, создаст общую сеть и запустит все сервисы в фоновом режиме (флаг **-d**)
    * *docker compose down* - аккуратно останавливает все сервисы из файла и удаляет их контейнеры и сети, оставляя систему чистой.
