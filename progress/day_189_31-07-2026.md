# День 189 (31.07.2026): Фикстуры (Fixtures) и Параметризация
## Теория:
* Концепция фикстур (@pytest.fixture): как избавиться от дублирования кода подготовки данных и инфраструктуры между тестами (Dependency Injection в pytest).
* Жизненный цикл фикстуры и yield: использование yield вместо return для разделения кода на этап подготовки (Setup) и этап очистки после теста (Teardown).
* Области видимости фикстур (Scopes): различия между function (создается для каждого теста), class, module и session (создается один раз на весь запуск) — когда какой скоуп использовать для оптимизации скорости тестов.
* Конфигурационный файл conftest.py: назначение файла в корню тестов, авто-обнаружение фикстур и шеринг контекста между всеми файлами без явного импорта.
* Параметризация тестов (@pytest.mark.parametrize): как запустить один и тот же тестовый сценарий на десятках различных наборов входных и выходных данных, не плодя дублирующий код.
## Практика:
* Создай файл tests/conftest.py и вынеси туда общие фикстуры (например, создание тестового пользователя или генератор данных).
* Напиши фикстуру db_session, которая подготавливает тестовые данные, отдаёт их в тест через yield, а после завершения теста подчищает данные в базе или закрывает соединение.
* Создай фикстуру со скоупом session для чтения тестовой конфигурации из .env.test.
* Используй декоратор @pytest.mark.parametrize, чтобы проверить валидатор email-адресов на списке из 5 валидных и 5 невалидных строк в рамках одной тестовой функции.

## Конспект изученных материалов
### 1. Концепция фикстур
* **Своими словами:** Вместо того чтобы каждый раз вызывать функцию подготовки данных в функция тестов, используются фикстуры. Фикстуры это функции которые подготавливают данные и используются данными через паттерн внедрения зависимостей. Фикстуры сами подготавливают данные, и чтобы использовать их нужно просто указать его имя в тестах
### 2. Жизненный цикл фикстур
* **Своими словами:**когда нужно не только подготовить данные и отдать, но и очистить за собой после работы жизненный цикл фикстур разделяется на две части:
    * **Setup:** здесь подготавливаются все необходимые данные (открывается БД, изменяются некоторые данные). Это часть кода до *yield*
    * **Teardown:** здесь убираются изменения которые были сделаны на этапе подготовки (закрывается БД, данные приходят в прошлое состояние). Это часть кода после *yield*
    * А yield это генератор который после подготовки данных не останавливая выполнение функции, замораживает его, отдаёт данные, а потом размораживает чтобы он выполнил остальную часть работы
### 3. Области видимости фикстур
* Если фикстура делает тяжёлые операции (инициализация тяжелой БД и т.п.) то вызывать его в каждом тесте заново с нуля было бы медленно. pytest позволяет настраивать область видимости:
    * *function*: фикстура создает новые данные для каждого функции теста
    * *class*: создает один раз для всего тестового класса
    * *module*: создает данные один раз для всего файла (test_...)
    * *session*: создает данные один раз для всего запуска pytest
* **Синтаксис:** *@pytest.fixture(scope='__scope_name__')
### 4. Конфигурационный файл
* **conftest.py:** когда тестов очень много, писать в каждом из них отдельные фикстуры, или же импортировать в друг друга было бы неправильным. И поэтому в корне папки тестов создается файл conftest.py в котором собраны самые необходимые или тяжелые фикстуры, и другие настройки тестов, которые каждый модуль тестов может импортировать без проблем. pytest сам умеет сканировать и читать содержимое конфигурационного файла.
### 5. Параметризация тестов
* Если есть функция, например валидации пароля. В нём могут быть условия что пароль не должен быть короче, или без спецсимволов и т.д. И в таком случае писать много тестов для каждого варианта пароля чтобы протестирвать только одну функцию заняло бы огромное место и было бы дублированием кода. Но, pytest позволяет параметризировать тесты, и вместо того чтобы писать 10 разных тестов (пример) можно в одном тесте протестировать всевозможные варианты. **Для этого используется декоратор:** *@pytest.mark.parametrize()*
