# День 209 (05.08.2026): Настройка CI/CD пайплайна и боевой Деплой
## Теория:
* Пайплайн (Pipeline): автоматизированная цепочка шагов, которую проходит код от момента коммита до попадания на сервер (Линтинг -> Тестирование -> Сборка Docker-образа -> Деплой).
* Секреты в CI/CD: как безопасно передавать ключи от базы данных и токены в GitHub Actions, не "засветив" их в публичном репозитории (GitHub Secrets).
* Стратегии отката (Rollback): что делать, если после деплоя всё сломалось. Понимание того, как быстро вернуть предыдущую стабильную версию Docker-контейнера.
* Финальная проверка инфраструктуры: ревью настроек Nginx (или другого reverse-proxy), SSL-сертификатов (HTTPS) и работы Health Checks.
## Практика:
* Открой файл пайплайна .github/workflows/deploy.yml (или создай его). Настрой строгую последовательность: деплой должен запускаться только если тесты и линтеры прошли успешно (needs: test).
* Зайди в настройки репозитория на GitHub (Settings -> Secrets and variables -> Actions) и добавь туда все нужные переменные (пароли от боевой БД, ключи шифрования, IP сервера).
* Сделай коммит и отправь код в ветку main. Открой вкладку Actions в GitHub и проследи за зелеными галочками на каждом этапе пайплайна.
* Открой боевой URL своего проекта в браузере. Проверь работу HTTPS и дерни эндпоинт /health, чтобы убедиться, что приложение "живо".
* Проведи ручное Smoke-тестирование (Дымовое тестирование) на живом сервере: зарегистрируй пользователя, войди в систему, создай запись.

## Конспект изученных материалов
### 1. CI/CD Пайплайн
* **CI/CD (Continous Integration/Continous Deployment)** - это процесс автоматизации сборки, тестирования и доставки кода. Вместо того чтобы вручную заходить на сервер по SSH, скачивать изменения через git pull и перезапускать сервисы, настраиваивается Runner, который выполняет эту цепочку шагов при каждом git push в ветку main
### 2. Секреты в CI/CD
* **Своими словами:** секретные данные нельзя публиковать в публичный репозиторий и нужно добавлять в .gitignore. Но, чтобы CI/CD пайплайн мог брать эти секретные данные безопасно, используется Зашифрованные секреты, например GitHub Actions Secrets. Чтобы передавать эти секреты в Pipeline, в нём нужно просто обратиться к нему по такому синтаксису: *${{ secrets.SECRET_KEY }}. И при запуске GitHub Actions сам поставит эти значения.
### 3. Стратегии отката.
* **Своими словами:** При деплое приложения на сервер, новая версия приложения может не работать, и ждать пока будет запускаться новый CI/CD с старой версией приложения занимает время. Вместо этого можно просто войти в сервер, и на сервере запустить старый образ приложения по хэшу образа.
