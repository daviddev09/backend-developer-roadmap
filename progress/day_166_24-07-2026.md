# День 166 (24.07.2026): Изоляция, порты и переменные окружения
## Теория:
* Сетевая изоляция: контейнеры работают в своей внутренней сети. Чтобы веб-сервер внутри контейнера был доступен из браузера твоего компьютера, нужен «проброс портов» (флаг -p внешний_порт:внутренний_порт).
* Переменные окружения: как передавать настройки внутрь контейнера при запуске без изменения самого кода (флаг -e КЛЮЧ=ЗНАЧЕНИЕ).
* Интерактивный режим: как "зайти" внутрь работающего контейнера и выполнять там команды Linux, словно это отдельный сервер (команда docker exec -it <имя_контейнера> bash).
* Просмотр логов: как читать то, что выводит приложение внутри контейнера (команда docker logs -f <имя_контейнера>).
## Практика:
* Запусти контейнер Nginx, пробросив порт 8080 твоего компьютера на внутренний порт 80 контейнера: docker run -d -p 8080:80 nginx.
* Открой браузер (или используй команду curl localhost:8080 в терминале) и убедись, что видишь стартовую страницу Nginx.
* Запусти базу данных PostgreSQL, передав ей обязательный пароль через переменную окружения: docker run -d -e POSTGRES_PASSWORD=mysecret postgres.
* Зайди внутрь работающего контейнера Postgres командой docker exec -it <id_контейнера> bash и посмотри файлы внутри с помощью стандартной Linux-команды ls.
* Выйди из контейнера командой exit, останови и удали все созданные сегодня контейнеры.

## Конспект изученных материалов
### 1. Сетевая изоляция и проброс портов
* По умолчанию каждый контейнер Docker запускается в полностью изолированном сетевом пространстве имен (Network Namespace). У каждого контейнера есть:
    * Свой собственный виртуальный интерфейс
    * Свой собственный IP-адрес внутри приватной подсети Docker
    * Своя таблица маршрутизации и собственное пространство портов
* Компьютер и браузер не имеют прямого доступа к временной сети Docker. Чтобы открыть доступ к приложению применяется **проброс портов** (Port Mapping/Port Building). Docker создает правило перенавправления сетевого трафика, связывающее порт твоей реальной машины с портом внутри контейнера.
* **Как это делается:** С помощью флага -p: *docker run -p <порт хоста>:<порт контейнера> <имя образа>*.
    * **<порт хоста>**: порт на твоем реальном компьютере, к которому ты обращаешься из браузера или программы.
    * **<порт контейнера>**: порт, на котором приложение реально работает внутри контейнера.
### 2. Переменные окружения
* Одно из главных правил современной разработки гласит: Конфигурация приложения должна быть отделена от кода и храниться в переменных окружения. Представь, что твое приложение использует базу данных. В режиме разработки адрес БД - localhost, а в боевом режиме - db.production.company.com. Тебе не нужно пересобирать Docker-образ под каждое окружение. Ты собираешь образ один раз, а динамические параметры передаешь при запуске контейнера
* **Примеры:**
    1. *docker run -d --name my_postgres -e POSTGRES_DB=app_db -e POSTGRES_USER=postgres -e POSTGRESS_PASSWORD=supersecretpass -p 5432:5432 postgres:16-alpine* - Передача одиночных переменных. Удобно когда нужно передавать мало переменных, кошмар если нужно передать много переменных.
    2. *docker run -d --name my_postgres --env-file config.env ip 3000:3000 postgres:16-alpine* - Использование файла с переменными. Для этого нужно чтобы файл .env был.
### 3. Интерактивнйый режим 
* Чтобы войти внутрь уже работающего контейнера, не останавливая его, используется комада:
    * *docker exec -it <мя контейнера> bash* - если стоит миинимальная ОС alpine, то bash заменить на sh
    * *docker exec -it <имя контейнера postgres> psql -U <user> -d <db_name>* - Подключится к базе данных Postgres внутри контейнера
    * *docker exec <имя контейнера nginx> ls -la /etc/nginx* - проверить содержимое папки внутри контейнера
    * написать: *exit* для выхода из контейнера
* Разбор флагов -i и -t (-it):
    * **-i** (interactive): оставляет открытым стандартный поток ввода (STDIN). Это позволяет передавать команды с клавиатуры внутрь контейнера
    * **-t** (--tty): выделяет псевдотерминал (TTY). Он обеспечивает форматирование, цветную подсветку теста и приглашение командной строки.
    * Вместе эта комбинация флагов -it превращает консоль в полнеценную командную строку внутри контейнера Linux
### 4. Просмотр и отслеживание логов контейнеров
* Приложение, запущенное в контейнере должно выводить сообщения в стандартный поток (STDOUT) или поток ошибок (STDERR). Docker перехватывает эти потоки и сохраняет их в специальный файл на диске хост-системы. Команда *docker logs* позволяет читать эти записи без необходимости заходить внутрь контейнера. Пример команды:
    * *docker logs <имя контейнера>* - показывает все логи конкретного контейнера
    * *docker logs --tail 20 <имя контейнера>* - показыввает последние 20 строк логов
    * *docker logs -f -t <имя контейнера>* - отслеживает логи в реальном времени с метками времени
    * *docker logs -f --tail 50 <имя контейнера>* - показывает последние 50 строк и продолжит отслеживать новые.
    * **Чтобы выйти из режима отслеживания логов, нажать комбинацию клавиш: Ctrl+C**
* **Ключевые флаги команды:**
    1. *docker logs <имя контейнера>* - выводит есь архив логов с момента первого старта контейнера.
    2. *-f* (follow) - режим "живого" времени. Консоль не завершает работу, а отсаётся открытой и печатает новые строки логов по мере их появления
    3. *--tail <число строк>* - показывает только последние N строк
    4. *-t* (--timestamps) - добавляет точную дату и время к каждой строке лога
