# День 176 (27.07.2026): Основы переменных окружения и файл .env
## Теория:
* Концепция переменных окружения (Environment Variables): что это такое на уровне операционной системы и как программы получают к ним доступ.
* Почему нельзя хардкодить чувствительные данные (пароли, API-ключи) прямо в исходном коде.
* Что такое файл .env: стандарт де-факто для хранения локальных секретов проекта в формате КЛЮЧ=ЗНАЧЕНИЕ.
* Самое важное правило безопасности: файл .env никогда не должен попасть в историю коммитов. Зачем и как использовать .gitignore для его скрытия.
* Знакомство с библиотеками для чтения таких файлов (например, python-dotenv, если ты пишешь на Python).
## Практика:
* Создай новый проект и сразу добавь файл .gitignore, прописав в нем строку .env.
* Создай файл .env и добавь туда пару строк: SECRET_KEY=my_super_secret и DEBUG=True.
* Сделай коммит и убедись, что .env не попал в Git (выполни git status).
* Напиши простой скрипт, который загружает переменные из .env с помощью библиотеки (например, dotenv.load_dotenv()) и выводит их значения в консоль через стандартные средства языка (например, os.getenv('SECRET_KEY')).

## Конспект изученных материалов
### 1. Концепция переменных окружения
* Переменные окружения это массив строк вида: Ключ=Значение которые хранятся на уровне ОС. Когда программа запускается ОС выделяет его процессу память и внутри этой памяти хранятся системные переменные окружения например: PAH, User. И также переменные окружения приложения. Суть концепции в том что программа может обратится к ОС и получить от него нужные для себя данные, например "DATABASE_URL". Таким образом программа становиться универсальной умея работать абсолютно везде, меняются только внешние настройки ОС в которой она запущена
### 2. Почему нельзя хардкодить секретные данные в коде
* **Своими словами:** слово "хардкодить" означает: Прописывать настройки приложения в коде. Хардкодинг порождает ряд пробелем. Например:
    * **Дыра в безопасности:** Если такой код попадает в публичный репозиторий его любой может прочитать и получить доступ к БД, телеграм боту, серверу и т.д. И даже если код не попадает в публичный репозиторий а будет лежать в приватном репозитории, не всем коллегам нужно видеть секретные данные приложения.
    * **Гибкость кода:** на самом деле нужно использовать один и тот же код сначала на тестовом сервере, а потом на боевом и если в коде настройки захардкодены то каждый раз придётся менять код приложения. 
### 3. Что такое файл .env
* **Своими словами:** это просто текстовый файл в котором секретные данные проекта хранятся в виде: Ключ=Значение.
* **Пример данных в .env:**
    * *DATABASE_URL=postgresql+asyncpg://postgres:password@host:port/db*
    * *JWT_SECRET=your_jwt_secret_key*
    * *TELEGRAM_BOT_TOKEN=your_token*
    * *API_PORT=8000*
### 4. Самое важно правило безопасности .env
* **Своими словами:** самое важное правило безопасности .env это не дать ему попасть в историю коммитов Git а также публичный репозиторий. Для того чтобы это реализовать, в самом начале когда Git инициализируется в рабочей директории, до того как создать файл .env и прописать в нём секретные данные, нужно создать файл **.gitignore** и настроить его так чтобы он не следил за этим файлом. После этого Git станет слепым по отнешению к файлам или директориям которые прописаны в **.gitignore**, и они никогда не попадут в истории коммитов.
* **Пример .gitignore:**
    * .env
### 5. Знакомство с библиотеками чтения
* **Своими словами:** на Python чтобы читать данные из .env используется библиотека: **python-dotenv**. Ведь само по себе ОС не читает данные из файла .env, а эта библиотека берёт этот файл, читает в нём данные, и добавляет их в переменные окружения ОС для текущего процесса. А потом библиотека **os** читает их из переменных окружения. 
* **Пример как это реализовать:**
> *import os*
> *from dotenv import load_dotenv*
>
> *load_dotenv()*
>
> *DATABASE_URL = os.getenv('DATABASE_URL')*
