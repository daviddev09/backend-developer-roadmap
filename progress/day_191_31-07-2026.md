# День 191 (31.07.2026): Тестирование асинхронного кода и REST API
## Теория:
* Специфика асинхронного тестирования: почему обычный pytest падает при попытке запустить async def test_*(), и как работает плагин pytest-asyncio.
* Интеграционное тестирование API: разница между юнит-тестами отдельных функций и интеграционными тестами HTTP-эндпоинтов.
* Инструменты для тестирования веб-каркасов: использование TestClient (Starlette/FastAPI) или httpx.AsyncClient для отправки виртуальных HTTP-запросов к приложению без запуска реального веб-сервера.
* Подмена зависимостей API (Dependency Overrides): как подменить реальную базовую БД на тестовую (например, SQLite in-memory или изолированную PostgreSQL) при тестировании эндпоинтов.
## Практика:
* Установи необходимые библиотеки: pip install pytest-asyncio httpx.
* Настрой pytest-asyncio (добавь @pytest.mark.asyncio на асинхронные тестовые функции или настрой asyncio_mode = auto в pytest.ini).
* Создай фикстуру client, возвращающую AsyncClient для твоего FastAPI/Web-приложения.
* Напиши интеграционный тест для POST /api/v1/users: отправь JSON с данными нового пользователя, проверь статус ответа 201 Created и структуру вернувшегося JSON.
* Напиши тест на обработку ошибок: отправь некорректные данные и убедись, что API возвращает статус 422 Unprocessable Entity или 400 Bad Request.
* Используй механизм app.dependency_overrides, чтобы на время интеграционных тестов API использовало тестовую базу данных вместо боевой.

## Конспект изученных материалов
### 1. Специфика асинхронного тестирования
* Обычный pytest не умеет работать с асинхронным кодом. Если написать асинхронную тестовую функцию, pytest не сможет его отработать. Потому что асинхронная функция нуждается в Event Loop. Плагин pytest-asyncio решает эту проблему. 
### 2. Интеграционное тестирование API
* **Своими словами:** интеграционные тесты это важная часть тестов любого API приложения. Если юнит тесты тестируют лишь независимые функции, то интеграционные тесты задействуют цепочку функций зависимых от других функций, например: от эедпоинта, до методов репозитория.
### 3. Инструменты: TestClient и httpx.AsyncClient
* **Своими словами:** Чтобы при интеграционных тестах не запускать реальный сервер который будет занимать время, используются специальные инструменты. Они умеют использовать эндпоинты прямо внутри RAM что делает их невероятно быстрыми.
### 4. Подмена зависимостей
* **Своими словами:** Подмена зависимостей (Dependency overrides) это одна из мощных возможностей FastAPI для тестов. Каждый эндпоинт может зависеть от чего-то, например от функции: get_db. Но если он будет зависеть от этой функции во время тестов, то откроется настоящая БД и там уже появятся ряд проблем. Поэтому через подмены зависимостей можно подменить реальную БД, на какой-то файловый БД sqlite или же тестовый СУБД
