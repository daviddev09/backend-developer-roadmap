# День 170 (25.07.2026): Связывание контейнеров, Сети и Volumes
## Теория:
* Сети в Compose (Networks): Docker Compose автоматически создает общую виртуальную сеть для всех сервисов в файле. Контейнеры могут обращаться друг к другу просто по именам сервисов (например, вместо IP-адреса база данных будет доступна по хосту db).
* Порядок запуска: инструкция depends_on, которая указывает, что веб-сервер должен стартовать только после базы данных.
* Постоянное хранилище (Volumes): контейнеры эфемерны. Если удалить базу данных, все данные пропадут. Volumes решают эту проблему, сохраняя данные на твоем основном жестком диске.
* Настройка Volumes в Compose: блок volumes на уровне сервиса и на уровне всего файла.
## Практика:
* Обнови свой docker-compose.yml. Создай два сервиса: app (твое приложение из Дня 167 или любой готовый образ) и db (база данных postgres).
* Для сервиса db настрой environment с паролем и добавь блок volumes для сохранения данных PostgreSQL (- pg_data:/var/lib/postgresql/data).
* Добавь в конец файла глобальный блок volumes: pg_data:.
* Подними связку docker compose up -d. Зайди в БД, создай любую тестовую таблицу.
* Сделай docker compose down (это удалит контейнеры), а затем снова docker compose up -d. Убедись, что твоя созданная таблица никуда не исчезла благодаря Volume.

## Конспект изученных материалов
### 1. Сети в Compose
* **Своими словами:** Когда поднимается инфраструктура через docker-compose.yml не нужно там прописывать вручную IP-адреса для связи контейнеров. Docker Compose сам создает общую виртуальную сеть для всех сервисов в файле. Можно просто написать имя сервиса вместо IP-адреса, например: *DB_HOST=db*, при создании контейнера db он сам зарезервирует в его имя его IP-адрес, и когда приложение будет обращаться к нему, он будет обращаться по адресу: *httр://db*, Docker проверит и если есть IP-адрес под этим именем он свяжет их. С таким подходом даже не нужно пробрасывать порты базы данных наружу (через ports), если доступ к ней нужен только приложению. 
### 2. Порядок запуска
* По умолчанию Docker compose пытается запустить все конетйнеры одновременно, чтобы сэкономить время, но, если FastAPI приложение соберётся первым а База данных ещё не успеет настроиться чтобы начать принимать подключения и т.п. приложение падает. Для решения этой проблемы применяется инструкция *depends_on*, которая указывает, что веб-сервер должен стартовать только после базы данных.
### 3. Постоянное хранилище
* Если хранить данные прямо внутри контейнера БД, то из-за причины что "Контейнеры эфемерны" и при перезапуске контейнеров или при удалении все данные пропадут. **Volumes** решает эту проблему, сохраняя данные на основном жестком диске.
* **Том** (Volume) - это специальная папка на сервере/ПК, которую Docker монтирует внутрь контейнера. Даже если полностью удалить контейнер БД, сами файлы с таблицами останутся в полной безопасности на хосте.
### 4. Настройка Volumes в Compose
* Настройка Volumes в Compose состоит из блока **volumes** на уровне сервиса и на уровне всего файла. Почему так? 
    * **Своимми словами:** Блок **volumes** на уровне файла делается для того чтобы при запуске контейнеров Docker создал "хранилище" для базы данных, в жёстком диске. То есть, Docker создаёт место в который могут записываться данные БД. А блок **volumes** на уровне сервиса подключает это "хранилище" из жесткого дика локальной системы (сервера, компьютера) к контейнеру Базы Данных, и таким образом контейнер может записывать данные на жёсткий диск
