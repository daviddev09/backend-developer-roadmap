# День 164 (23.07.2026): Удаленный доступ (SSH) и передача файлов
## Теория:
* Протокол SSH (Secure Shell): почему это стандарт индустрии для безопасного подключения к серверам.
* Асимметричное шифрование: концепция приватного (закрытого) и публичного (открытого) ключей. Где они хранятся (директория ~/.ssh).
* Генерация SSH-ключей: разбор команды ssh-keygen и современных алгоритмов (например, Ed25519).
* Как работает аутентификация по ключу без пароля: копирование публичного ключа на удаленный сервер командой ssh-copy-id.
* Безопасная передача файлов по сети: основы работы с командой scp (Secure Copy).
## Практика:
* Сгенерируй новую пару SSH-ключей на своей локальной машине с алгоритмом Ed25519: выполни ssh-keygen -t ed25519 -C "твоя_почта@example.com".
* Перейди в папку ~/.ssh и посмотри через ls -l на созданные файлы (публичный ключ .pub и приватный без расширения).
* Выведи содержимое своего публичного ключа в консоль с помощью cat. Именно этот текст добавляют на GitHub или на удаленные серверы.
* Изучи синтаксис команды scp (на практике без реального сервера выполнить ее до конца не выйдет, но важно понять конструкцию: scp local_file.txt user@server_ip:/remote/path/).

## Конспект изученных материалов
### 1. Протокол SSH
* **SSH (Secure Shell)** - это сетевой протокол который позволяет безопасно управлять удаленным компьютером. Весь трафик внутри SSH-соединения зашифрован. Даже если злоумышленник перехватит пакеты данных, он увидит лишь бессмымленный набор символов
### 2. Асимметричное шифрование
* В основе безопасности SSH лежит асимметричное шифрование. В отличие от обычного пароля (симметричного), здесь используется пара ключей, математически связанных друг с другом:
    1. Публичный ключ - Хранится на сервере
    2. Приватный ключ - Хранится на локальном компьютере.
### 3. Генерация SSH-ключей
* Чтобы получить эту пару ключей нужно их сгенерировать используя алгоритм: **Ed25519**. Он быстрее, безопаснее и генерирует ключи меньшего размера.
* **Команда генерации:**
    * *ssh-keygen -t ed25519 -C 'your_email@example.com'
    * *-t ed 25519*: Указывает тип алгоритма
    * *-C '...':* Комментарий (обычно почта), чтобы ты мог потом понять, кому принадлежит ключ.
### 4. Аутентификация без пароля
* SSH позволяет настроить вход по ключу. Суть проста: нужно взять публичный ключ (.pub) и положить его на удаленный сервер в специальный файл **~/.ssh/authorized_keys**. Используя команду:
    * *ssh-copy-id username@host
    * Потом попросят в последний раз ввести пароль от пользователя на сервере.
* **Как это работает под капотом:** Когда ты подключаешься, сервер видит твой публичный ключ и отправляет тебе случайную строку, зашифрованную этим ключом. Твой SSH-клиент её твоим приватным ключом и отправляет ответ. Сервер понимает: "он смог расшифровать, значит у него есть приватный ключ. Пропускаю!"
### 5. Безопасная передача файлов по сети
* Утилита **scp** (Secure Copy) копирует файлы также легко, как обычная команда cp копирует их локально. Синтакис: *scp <что копируем> <куда копируем>*:
    * *scp report.txt username@hostname:/home/username/* - Отправить локальный файл на удаленный сервер
    * *scp username@hostname:/home/username/report.txt* - Скачать файл с удаленного сервера на свой компьютер
    * *scp -r Phone_store_API/ username@hostname:/home/username/* - Скопировать всю папку со всем её содержимым
### Важные команды
* *ssh-keygen -t -f ~/.ssh/id_ed25519_daviddev -C 'daviddev@example.com* - Генерация ключей с кастомным именем
* *ssh-copy-id -i ~/.ssh/id_ed25519_daviddev.pub username@hostname* - Копирование кастомного ключа на сервер
* *ssh -i ~/.ssh/id_ed25519_daviddev username@hostname* - Подключение к серверу по кастомному ключу
* *scp -i ~/.ssh/id_ed25519_daviddev <Path to file> username@hostname:/<path>* - Копирование файла к серверу с кастомным ключом
* *scp -i ~/.ssh/id_ed25519_daviddev -r <Path to directory> username@hostname:/<path>* - Копирование папки и всего содержимого к серверу с кастомным ключом
* *scp -i ~/.ssh/id_ed25519_daviddev <Path to file/directory> username@hostname:~* - Копирование файла/папки к серверу в директорию текщуго пользователя (тильда ~)
