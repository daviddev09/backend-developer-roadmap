# День 194 (01.08.2026): Тестирование аутентификации и защищенных маршрутов
## Теория:
* Стратегии тестирования авторизации: генерация валидных токенов (JWT) прямо в тестах против подмены зависимостей (Dependency Overrides) проверки прав.
* Фабрики тестовых данных (Test Data Factories): паттерн создания фикстур, которые генерируют пользователей с разными ролями (админ, обычный юзер, заблокированный юзер) для каждого теста.
* Негативное тестирование безопасности: почему важно проверять не только успешный вход, но и правильную реакцию системы на отсутствие токена или просроченный токен (статусы 401 и 403).
# Практика:
* Напиши функцию-помощник или фикстуру, которая создает в тестовой БД пользователя и генерирует для него валидный JWT-токен (или сессионную куку).
* Создай фикстуру auth_client, которая берет базовый тестовый клиент и автоматически подставляет в него заголовок Authorization: Bearer <token>.
* Напиши тест для защищенного маршрута (например, GET /api/users/me), используя auth_client, и убедись, что он возвращает статус 200 и данные профиля.
* Напиши два негативных теста для этого же маршрута: первый без заголовка авторизации (ожидаем 401 Unauthorized), второй — с токеном, у которого истек срок действия (ожидаем 401 или 403).
