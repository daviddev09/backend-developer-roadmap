# День 206 (05.08.2026): Алгоритмы Rate Limiting (Ограничение частоты)
## Теория:
* Что такое Rate Limiting и зачем он нужен: защита API от DDoS-атак, брутфорса паролей, парсинга (скрапинга) и справедливое распределение ресурсов между клиентами.
* Алгоритм Fixed Window (Фиксированное окно): подсчет запросов в текущей минуте. Его плюсы (простота) и минусы (всплески трафика на границе минут).
* Алгоритм Token Bucket (Маркерная корзина): стандарт индустрии. Как корзина наполняется "жетонами" с постоянной скоростью, и как каждый запрос забирает один жетон.
* Ключи для лимитов: как идентифицировать пользователя для ограничения (по IP-адресу, по API-ключу, по ID авторизованного пользователя).

## Конспект изученных материалов
### 1. Что такое Rate Limiting
* **Rate Limiting** - это механизм контроля трафика, который ограничивает количество запросов от одного клиента за определенный промежуток времени (например, 100 запросов в минуту).
### 2. Алгоритм Fixed Window (Фиксированное окно)
* Это самый простой и понятный алгоритм. Мы делим время на фиксированные отрезки (окна), например, с 12:00:00 до 12:01:00. Внутри этого окна считаем каждый запрос.
* **Как это работает:**
    1. Клиент делает запрос.
    2. Мы формируем ключ, привязанный к текущей минуте: *rate_limit:ip:192.168.1.1:minute:2026-08-05T12:00.*
    3. Увеличиваем значение по этому ключу на 1.
    4. Если значение > Лимита, отклоняем запрос.
* **Плюсы:** Очень легко реализовать, потребляет минимум памяти (один ключ на пользователя).
* **Минусы (Проблема границы):** Всплески трафика. Представь, что лимит 100 запросов в минуту. Хакер отправляет 100 запросов в 12:00:59 и еще 100 запросов в 12:01:01. Алгоритм пропустит оба пула (окна-то разные!), и сервер получит 200 запросов за 2 секунды.
### 3. Алгоритм Token Bucket (Маркерная корзина)
* Это индустриальный стандарт (его используют AWS, Stripe, Nginx). Алгоритм решает проблему всплесков трафика.
* **Аналогия:** Корзина, в которой лежит $N$ жетонов (максимальный лимит).
    * Каждый раз, когда пользователь делает запрос, он забирает 1 жетон из корзины.
    * Если корзина пуста — запрос отклоняется (429).
    * Параллельно работает "капельница", которая добавляет в корзину $R$ новых жетонов каждую секунду (скорость пополнения), пока корзина не заполнится до максимума.
### 4. Ключи для лимитов
* Прежде чем считать запросы, нам нужен уникальный идентификатор клиента (Ключ в Redis).
* **По IP-адресу (ip:192.168.1.5):**
    * Плюсы: Работает для неавторизованных пользователей.
    * Минусы: За одним IP может сидеть целый офис (NAT). Заблокировав IP, можно заблокировать 100 легитимных пользователей.
* **По ID пользователя (user:42):**
    * Плюсы: Идеально для авторизованных сессий.
    * Минусы: Не защитит открытые эндпоинты (регистрацию, логин).
* **По API-ключу (apikey:XYZ123):**
    * Плюсы: Стандарт для B2B (например, Stripe или OpenAI выдают разные лимиты в зависимости от купленного тарифа).
