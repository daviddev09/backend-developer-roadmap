# День 188 (31.07.2026): Основы pytest, структура тестов и паттерн AAA
## Теория:
* Отличие pytest от встроенного unittest: почему pytest стал стандартом в Python-разработке (лаконичный синтаксис, отсутствие необходимости создавать классы-наследники, использование стандартных выражений assert вместо self.assertEqual).
* Автоматический поиск тестов (Test Discovery): соглашения по именованию файлов (test_*.py или *_test.py), тестовых функций (test_*()) и директорий, которые pytest находит автоматически.
* Паттерн AAA (Arrange-Act-Assert): золотой стандарт структурирования unit-теста:
    * Arrange (Подготовка): настройка входных данных и окружения.
    * Act (Действие): вызов тестируемой функции или метода.
    * Assert (Проверка): сверка полученного результата с ожидаемым.
* Проверка исключений: использование контекстного менеджера pytest.raises() для проверки того, что код правильно реагирует на ошибочные данные и выбрасывает нужные Exception.
* Флаги запуска pytest в CLI: базовые команды для работы с тестами (-v для подробного вывода, -k для фильтрации по названию, -s для вывода print в консоль).
## Практика:
* Установи pytest в свое виртуальное окружение: pip install pytest.
* Создай в проекте отдельную папку tests/ и модуль бизнес-логики (например, services/calculator.py с функциями расчета скидок или валидации данных).
* Напиши 3–5 unit-тестов для функций в файле tests/test_calculator.py, явно разделив код каждого теста комментариями # Arrange, # Act, # Assert.
* Напиши тест, проверяющий, что передача отрицательного числа в функцию выбрасывает ValueError с помощью with pytest.raises(ValueError):.
* Запусти тесты из терминала, опробовав ключи pytest -v, pytest -k "test_discount" и pytest -s.

## Конспект изученных материалов
### 1. Отличие pytest от unittest
* **Своими словами:** Главное отличие это в их синтаксисе. Если в встроенном unittest чтобы написать тесты, нужно писать огромный код и классы для каждых функций, то в pytest это несколько строк кода и никаких сложных выражений.
### 2. Автоматический поискт тестов
* **Своими словами:** Автоматический поиск тестов проиходит по соглашению имен файлов. Чтобы начать тесты, в терминале нужноо ввести просто: *pytest* и он сам начнёт искать эти файлы, файлы тестов должна начинаться или заканчиваться так: *test_...* или *..._test* а также функции тестов внутри них должны быть такими: *def test_...*. Это строго должно быть так иначе pytest не сможет найти их.
### 3. Проверка исключений
* **Своими словами:** Иногда в тестах нужно тестировать не только правильный результат, но и то что валидирует ли функция входящие данные, и в случае чего выбрасывает ли ошибку. Для этого используется: *pytest.raises* с контекстным менеджером with:
    * *with pytest.raises(ValueError):*
        * вызов_функции
