# День 181 (28.07.2026): Основы облачного деплоя и подготовка приложения
## Теория:
* Разница между IaaS (классический VPS, например, DigitalOcean или AWS EC2) и PaaS (Render, Fly.io, Heroku). Почему PaaS идеально подходит для быстрого старта и современных Docker-приложений.
* Требования к Production-приложениям (методология 12-Factor App): отсутствие хардкода, логирование в стандартный поток вывода (stdout) и работа без сохранения состояния на диске (Stateless).
* Понятие эфемерной файловой системы (Ephemeral Storage): почему любые файлы (картинки, документы), сохраненные локально внутри контейнера на Render или Fly.io, навсегда исчезнут при следующем рестарте сервера, и почему для них нужны сторонние сервисы (например, AWS S3).
* Настройка порта: почему облачные провайдеры динамически назначают порт приложению и как правильно читать системную переменную $PORT вместо жестко заданного порта 8000.
* Боевой веб-сервер: разница между встроенным сервером для разработки и WSGI/ASGI серверами для продакшена (например, Gunicorn или Uvicorn).
## Практика:
* В своем проекте установи production веб-сервер (например, pip install uvicorn или gunicorn).
* Измени логику запуска приложения так, чтобы хост был строго 0.0.0.0 (чтобы приложение принимало запросы извне, а не только изнутри контейнера).
* Настрой чтение порта из переменных окружения. Если переменная PORT не задана, используй 8000 по умолчанию.
* Обнови файл requirements.txt (или аналог), чтобы в нем были зафиксированы все новые зависимости.
* Закоммить эти инфраструктурные изменения и отправь их в ветку main на GitHub.

## Конспект изученных материалов
### 1. Разница между IaaS и PaaS
* **IaaS (Infrastructure as a Service):** Дают голую операционную систему (например, чистую Ubuntu). И твоя задача сам настроить Nginx, SSL-сертификаты, управление systemd службами и безопасностью ОС.
* **PaaS (Platform as a Service):** Дают готовую платформу которая сама умеет собирать и запускать код. Твоя ответственность только написание кода и настройка переменных окружения.
### 2. Требования к Production-приложениям
* Чтобы код мог стабильно работать в облаке, он должен подчиняться правилам методологии 12-Factor App. Вот главные из них:
    * **Отсутствие хардкода:** Все конфигурации, ключи БД и пароли должны читаться строго из переменных окружения. Никаких .env файлов внутри скомпилированного Docker-образа быть не должно.
    * **Логирование в stdout:** Приложение не должно писать логи в файлы на диске. Оно должно выводить все логи в стандартный поток вывода stdout.
    * **Stateless:** Приложение не должно хранить данные о сессиях пользователей в своей оперативной памяти. Любые данные, которые должны пережить перезагрузку сервера, должны храниться в БД.
### 3. Понятие эфемерной файловой системы
* **Своими словами:** Контейнеры эфемерны, это значит что любые медиафайлы пользователей не должны храниться в хранилище контейнера, а также внутри файловой системы хостинга, ведь они могут перенести твоё приложение из сервера в США на Фракнфурт, и тогда твои данные пропадут, а данные в контейнерах при перезапуске очистяться. И поэтому приложение должно только принимать медиафайлы, а потом передавать их специальным сервисам объектного хранилища и в БД сохранить только ссылку на него.
### 4. Настройка порта
* Облачные провайдеры запускают тысячи контейнеров на одном физическом сервере и сами назначают порт приложению при каждом запуске, это может быть: 25822, 8091, ... И по этому приложение должно читать данные Порта из переменных окружения.
### 5. Боевой веб-сервер
* Боевой веб-сервер отличается тем что он готов к продакшену. Для этого используются специализированные WSGI (Web Server Gateway Interface, для синхронного кода) или ASGI (Asynchronus Server Gateway Interface, для асинхронного кода) серверы. Они умеют создавать несколько параллельных рабочих процессов, автоматически перезапускать упавшие процессы и эффективно обрабатывать тысячи одновременных запросов.
