# День 177 (27.07.2026): Типизация, валидация и файл .env.example
## Теория:
* Проблема типизации: почему любые данные, полученные из переменных окружения, по умолчанию являются строками (даже если там написано True или 8080), и как это может сломать логику.
* Проблема отсутствующих данных: что будет, если программа попытается прочитать переменную, которой нет в .env. Как задавать значения по умолчанию.
* Шаблоны конфигурации: зачем нужен файл .env.example (или .env.template) и почему его, в отличие от самого .env, нужно добавлять в Git.
## Практика:
* Создай в проекте файл .env.example и добавь в него ключи без реальных паролей (например, SECRET_KEY=your_key_here, PORT=8000). Сделай коммит.
* В своем коде попытайся прочитать переменную PORT и прибавь к ней число 10. Получи ошибку типов (сложение строки и числа).
* Исправь код, явно преобразовав переменную PORT в целое число (integer).
* Напиши проверку (if not key:), которая выбрасывает понятную ошибку и останавливает программу, если критически важная переменная (например, SECRET_KEY) не найдена.

## Конспект изученных материалов
### 1. Проблема типизиции
* **Своими словами:** любые данные, полученные из переменных окружений по умолчанию являются строками (даже если там написано True или 8000). Это потому что ОС хранит переменные окружения в виде простых строк. И если при получении например порта: *os.getenv('PORT')* попытаться измнеить его с 8000 на 8001, с помощью: *port = port + 1* это вызовит ошибку типа, ведь полученные данные порта являются строкой. Также и с булево значениями: если мы получаем булево значение *DEBUG=False* он всё равно будет True потому что в Python любая непустая строка это **True**.
### 2. Проблема отсутствующих типов
* **Своими словами:** если программа попытаеться прочитать значение (*os.getenv(...)*) которой нет в .env, оно вернёт None. Чтобы предотвратить это можно задать значение по умолчанию. Значение по умолчанию будет использоваться только когда os вернула None. Синтаксис:
    * *os.getenv('PORT', 8000) - 8000 это значение по умолчанию
### 3. Шаблоны конфигурации
* **Своими словами:** шаблоны конфигурации (файлы .env.example или .env.template) нужны для того чтобы дать понять какие переменные окружения использует программа. Например файл .env.example хранит в себе примеры секретных данных из файла .env, это нужно когда проект выкладывается в публичный репозиторий, те кто сачают его могли у себя локально взять и посмотреть какие данные нужны, а потом скопировать его переименовать в .env и подставить свои настоящие данные. 
* **Пример .env.example:**
    * *DATABASE_URL=your_url*
    * *JWT_SECRET_KEY=your_secret_key_here*
