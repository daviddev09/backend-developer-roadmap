# День 182 (28.07.2026): Развертывание облачной базы данных (Managed Database)
## Теория:
* Концепция управляемых баз данных (Managed DB): почему лучше доверить хостинг базы данных облачному провайдеру, чем разворачивать её вручную в Docker-контейнере на дешевом сервере (автоматические бэкапы, обновления, отказоустойчивость).
* Разница между Internal URL (внутренним адресом) и External URL (внешним адресом) базы данных.
* Почему внутренний адрес быстрее и безопаснее, и в каких случаях используется внешний (для локального подключения через клиенты типа DBeaver или pgAdmin).
* Безопасность облачных баз данных: как защитить БД паролем и почему важно не выставлять порты базы данных наружу без необходимости.
## Практика:
* Зарегистрируйся на выбранной платформе (например, Render.com) и создай новый ресурс типа "PostgreSQL".
* Дождись инициализации базы данных и найди на панели управления раздел с Connection Strings (строками подключения).
* Скопируй External Database URL.
* Открой локальный клиент для управления базами данных (DBeaver, DataGrip или pgAdmin), создай новое подключение, вставь скопированный URL и успешно подключись к облачной БД.
* Выполни тестовый SQL-скрипт (например, создай простую таблицу), чтобы убедиться, что у тебя есть права на запись в облачную базу.

## Конспект изученных материалов
### 1. Концепция управляемых баз данных
* Облачные провайдеры сами делают бекапы, переключают трафик на резервную копию если основной упадёт, провайдер патчит уязвимости, монитори графики CPU, RAM и медленные запросы из коробки.
### 2. Разница между Internal URL и External URL
* **Своими словами:** когда создаёшь базу данных в облачном провайдере он выдаёт два URL для подключения:
    * **Internal URL:** внутренний URL. Очень хорош если и База данных и приложение работают у одного провайдера. Потому что чтобы приложение мог подключиться к БД ему не нужно выходить в всемирный интернет. Плюс это обеспечивает надёжность данных ведь никто кроме тебя не может достучаться по этому адресу, провайдеры обычно не тарифицируют внутренний трафик и это даёт высокую скорость и минимальную задержку.
    * **External URL:** внешний URL. Нужен если приложение работает на хостинге другого провайдера, или если ты хочешь подключиться с своего компьютера и зайти через psql или DBeaver. Минусы в том что это работает медленно и высокие задержки, и также это менее безопасно для атак.
### 3. Почему внутренний адрес быстрее и безопаснее
* **Своими словами:** внутренний адрес быстрее потому что чтобы подключаться к БД, приложение не нужно выходить на весь интернет. Безопаснее потому что никто из улицы не может зайти по этому адресу, этот адрес работает только локально.
### 4. Безопасность облачных баз данных
1. **Не использовать External URL для боевого кода**
2. **Добавить IP Allowlisting (белые списки IP):** Если нужно использовать External URL, нужно зайти в настройки провайдера и указать свой домашний IP-адрес в пазделе "Trusted Sources" или "Firewall". Таким образом джае зная пароль хакер получит отказ в соединении на уровне сети
3. **Сложные пароли:** Облачные провайдеры обычно сами генерируют 32-символьные кракозябры.
4. **Переменные окружения .env:** Никогда не хардкодь строку подключения в коде.
