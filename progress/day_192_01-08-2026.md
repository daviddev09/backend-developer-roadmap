# День 192: Code Coverage (Покрытие кода тестами) и CI-интеграция
## Теория:
* Что такое Code Coverage: метрика, определяющая, какой процент исходного кода приложения исполнялся во время запуска тестового прогона.
* Типы покрытия: Statement Coverage (покрытие строк) и Branch Coverage (покрытие веток логики if/else).
* Мифы о 100% покрытии: почему 100% Coverage не гарантирует отсутствие багов, но низкий процент (<70%) почти гарантирует их наличие.
* Инструмент pytest-cov: генерация текстовых и HTML-отчетов по покрытию кода.
* Исключение файлов из анализа (.coveragerc): почему из отчетов нужно исключать файлы миграций, конфигураций, тестов и сторонних библиотек.
## Практика:
* Установи плагин для анализа покрытия: pip install pytest-cov.
* Запусти тесты с подсчетом покрытия и генерацией детального HTML-отчета:
    * pytest --cov=app --cov-report=html
* Открой сгенерированный файл htmlcov/index.html в браузере. Найди файлы с наименьшим процентом покрытия и посмотри, какие ветки кода (выделены красным) не были затронуты тестами.
* Допиши тесты для необработанных исключений и редких if/else условий, подняв общий процент покрытия проекта минимум до 80%.
* Создай в корне проекта файл конфигурации .coveragerc и укажи в нем правила исключения файлов.
* Добавь в пайплайн GitHub Actions шаг проверки покрытия с фатальным флагом: pytest --cov=app --cov-fail-under=80, чтобы автоматическая сборка падала, если разработчик забыл написать тесты на новый код.
