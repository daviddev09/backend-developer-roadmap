# День 167 (24.07.2026): Создание своих образов (Dockerfile)
## Теория:
* Что такое Dockerfile: это текстовый файл с пошаговыми инструкциями для Docker по сборке твоего личного образа.
* Базовый образ: инструкция FROM, которая указывает стартовую точку (например, чистый Linux или готовый образ с Python).
* Рабочая директория: инструкция WORKDIR, задающая папку внутри контейнера, где будут происходить все дальнейшие действия.
* Копирование файлов: инструкция COPY, которая переносит код с твоего компьютера внутрь образа.
* Выполнение команд при сборке: инструкция RUN (например, для установки зависимостей).
* Точка входа: инструкции CMD или ENTRYPOINT, которые указывают, какую команду должен запустить контейнер при старте.
* Команда сборки: docker build -t <имя_твоего_образа> . (точка в конце означает текущую директорию).
## Практика:
* Создай новую папку, а внутри неё файл app.py с простейшим скриптом, который выводит "Hello from my first Docker image!".
* В этой же папке создай файл с точным названием Dockerfile (без расширений).
* Напиши внутри инструкции: FROM python:3.10, затем WORKDIR /app, затем COPY app.py ., и в конце CMD ["python", "app.py"].
* Собери свой образ командой docker build -t my-python-app .
* Запусти контейнер из своего нового образа: docker run my-python-app и убедись, что скрипт отработал.

## Конспект изученных материалов
### 1. Что такое Dockerfile
* **Dockerfile** это обычный текстовый файл без расширения содержащий инструкции для Docker. Docker читает этот файл строго сверху вниз выполняя каждую инструкцию по порядку. Это как рецепт для приготовления блюда, где всё описывается шаг за шагом, но оно не для блюда а для того чтобы объяснить Docker какой образ создать. Чтобы сделать это в Dockerfile пишутся инструкции которые напишу ниже.
### 2. Базовый образ
* Каждый Dockerfile обязан начинаться с команды **FROM**. Ты не создаешь ОС с нуля, ты берешь заготовку. **Базовый образ**: Инструкция FROM, которая указвает стартовую точку (Например, чистый Linux или готовый образ Python). Он говорит Docker: "Возьми этот образ как основу". Пример:
    * *FROM python:3.13-slim*
### 3. Рабочая директория
* Если зайти в контейнер то по умолчанию ты окажешься в корневом каталоге: /. Сваливать туда файлы своего проекта - плохая идея. **Рабочая директория**: инструкция WORKDIR, задающая папку внутри контейнера, где будут происходить все дальнейшие действия. Если папки /app нет, Docker создаст её сам. Пример:
    * *WORKDIR /app*
### 4. Копирование файлов
* Пока код лежит только на компьютере. Его нужно перенести внутрь собираемого образа. **Копирование файлов**: инструкция COPY, которая переносит код с компьютера внутрь образа. Синтаксис: *COPY <откуда на компюбтере> <куда внутри контейнера>. Пример:
    * *COPY app.py .* - скопировать файл app.py из текущей папки хоста в текущую папку контейнера (. означает текущую папку контейнера /app)
    * *COPY . .* - первая точка означает текущую папку на компьютере, вторая точка означает текущую папку контейнера. То есть эта команда берёт всю папку на компьютере вместо одного файла (*COPY app.py*).
### 5. Выполнение команд при сборке
* Эта инструкция работает как терминал внутри контейнера в момент его сборки. **Выполнение команд при сборке**: инструкция RUN (например, для установки зависимостей). Пример:
    * *RUN pip install -r requirements.txt* - установить зависимости из файла requirements.txt
    * *RUN pip install fastapi* - установить библиотеку fastapi
### 6. Точка входа
* **Точка входа**: инструкции CMD или ENTRYPOINT, которые указывают, какую команду должен запустить контейнер при старте. Инструкция **CMD** это базовая комнда того что должен сделать контейнер при запуске, но, его можно переопределить. А вот **ENTRYPOINT** используется когда не пологается что нужно будет переопределять команду запуска, и поэтому его изменить сложно. Пример:
    * *CMD ["python", "app.py"]
### 7. Команда сборки
* Когда **Dockerfile** готов, его нужно превратить в бинарный образ. **Команда сборки**: *docker build -t <имя образа> .* (Точка в конце означает текущую директорию)
    * Флаг **-t** (tag) дает новому образу понятное имя (иначе это будет просто случайный хэш)
    * Точка **.** в конце невероятно важна. Она говорит демону Docker: "Ищи файл Dockerfile и все файлы проекта (contexy) в той папке, где Я сейчас нахожусь".
### Пример Dockerfile из практической задачи
* *FROM python:3.13-slim*
* *WORKDIR /app*
* *COPY app.py .*
* *CMD ["python", "app.py"]*
