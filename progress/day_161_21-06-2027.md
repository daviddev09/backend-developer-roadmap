# День 161 (21.07.2026): Права доступа и владельцы файлов
## Теория:
* Модель безопасности Linux: концепция пользователя (User), группы (Group) и всех остальных (Others).
* Чтение прав доступа: что означают символы r (read), w (write) и x (execute) в выводе команды ls -l.
* Цифровое представление прав: как переводить rwx в числа (4 для чтения, 2 для записи, 1 для выполнения) и что значат комбинации вроде 777, 644 или 755.
* Изменение прав доступа с помощью chmod: использование числового (например, chmod 600) и символьного (например, chmod u+x) режимов.
* Смена владельца файла и группы с помощью chown.
* Зачем нужна команда sudo и концепция суперпользователя (root).
## Практика:
* Создай файл script.sh и напиши внутри echo "Hello Linux".
* Проверь его права с помощью ls -l. Попробуй запустить его командой ./script.sh и получи ошибку "Permission denied".
* Выдай файлу права на исполнение только для текущего пользователя с помощью chmod u+x script.sh.
* Запусти скрипт снова и убедись, что он отработал.
* Измени права на файл так, чтобы никто, кроме тебя (владельца), не мог его даже прочитать (права 600).

## Конспект изученных материалов
### 1. Модель безопасности Linux
* В Linux у каждого файла и папки есть строгая привязка к тому, кто имеет право с ним работать. Все пользователи делятся на три категрии:
    * **User (Владелец/u):** Тот, кто создал файл (по умолчанию). У него больше всего прав.
    * **Group (Группа/g):** Группа пользователей, которым назначены определенные права на этот файл. Это удобно, когда над одним проектом работает несколько человек.
    * **Others (Остальные/o):** Все остальные пользователи системы, которые не являются владельцами и не входят в группу.
### 2. Чтение прав доступа
* Когда вводишь команду *ls -l*, слева от каждого файла видишь непонятную строку из 10 символов, например: *-rwxr-xr--*. Давай её расшифруем. Первый символ указывает на тип (например **-** это файл, **d** директория). Остальные 9 символов делятся на три блока по три символа (Владелец, Группа, Остальные). Сами буквы означают:
    * **r (read):** Право на чтение
    * **w (write):** Право на запись
    * **x (execute):** Право на выполнение
    * **-:** Отсутствие права.
### 3. Цифровое представление прав
* Чтобы не писать длинные строки вроде: *rwxrw-r--*, системные администраторы используют цифры. Каждому праву присвоен свой "вес":
    * **Буква**---**Право**---**Цифровое значение**
    * **r**---**Чтение**---**4**
    * **w**---**Запись**---**2**
    * **x**---**Выполнение**---**1**
    * **-** ---**Нет прав**---**0**
* Чтобы получить итоговую цифру для категории, мы просто складываем веса. Например, мы хотим дать права на чтение (4) и запись (2), но без выполнения (0). Считаем 4+2+0=6
* Популярные комбинации (сразу для всех трех категорий U-G-O):
    * **777:** *rwxrwxrwx* - Полный доступ для всех
    * **755:** *rwxr-xr-x* - Владелец может всё (7), а группа и остальные могут только читать и загружать (5)
    * **644:** *rw-r--r--* - Владелец может читать и писать (6), остальные только читать (4). Стандарт для обычных текстовых файлов.
### 4. Изменение прав доступа
* Команда **chmod (Change Mode)** меняет эти самые права. У неё есть два режима:
    1. *chmod 600 config.txt* Цифровой режим быстрый и частый
    2. *chmod u+x script.sh*, *chmod o-w script.sh* Символьный режим. Здесь мы используем буквы u (user), g (group), o (others), a (all), плюсы (+) и минусы (-)
### 5. Смена владельца
* Команда **chown (Change Owner)** позволяет передать файл другому пользователь или группе:
    * *chown alice document.txt* Передать файл пользователю alice
    * *chown alice:developers document.txt* Передать файл пользователю alice и группе developers одновременно
### 6. Суперпользователь (root) и **sudo**
* В Linux есть абсолютный Бог системы - пользователь **root**. Ему плевать на любые ограничения и права **chmod**, он может прочитать, изменить или удалить абсолютно любой файл (даже жизненно важный для самой ОС).
* Сидеть под **root** постоянно - это прямой путь к случайному уничтожению сервера. Поэтому была придумана утилита **sudo** (SuperUser DO). Она позволяет обычному пользователю (если ему разрешили) временно "надеть корону" и выполнить одну конкретную команду с правами администратора:
    * *cat /etc/shadow* Ошибка: Permission denied. Обычный пользователь не может менять системные настройки.
    * *sudo cat /etc/shadow* Успех (попросит пароль пользователя).
