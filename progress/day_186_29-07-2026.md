# День 186 (29.07.2026): Продвинутое логирование и сбор метрик
## Теория:
* Разница между логами и метриками: логи — это записи о событиях (кто зашел, какая ошибка случилась), а метрики — это числа во времени (сколько памяти занято, сколько запросов в секунду).
* Структурированное логирование (JSON logs): почему в продакшене нельзя писать логи обычным текстом. Разбор того, как JSON-формат позволяет системам аналитики (например, ELK Stack или Datadog) мгновенно фильтровать миллионы строк по конкретному user_id или request_id. * Уровни логирования (Log Levels): почему на боевом сервере нужно отключать уровень DEBUG и оставлять только INFO, WARNING, ERROR и CRITICAL, чтобы не засорять диск и не "сливать" чувствительные данные.
* Алертинг (Alerting) на основе логов: как системы мониторинга читают твои ошибки и понимают, когда нужно срочно будить разработчика.
## Практика:
* Установи в свой проект библиотеку для продвинутого логирования (например, loguru или structlog для Python).
* Настрой вывод логов так, чтобы в консоль (stdout) они падали в формате JSON.
* Добавь в код чтение переменной LOG_LEVEL из файла .env (или системного окружения), чтобы уровень логов можно было менять без переписывания кода.
* Задеплой обновление на сервер, вызови искусственную ошибку (например, обратись к несуществующему маршруту) и посмотри в панели облачного провайдера, как красиво и структурированно теперь выглядит эта ошибка.

## Конспект изученных материалов
### 1. Разница между логами  и метриками
* **Логи** это дискретные записи о событиях.
    * Это текстовая или структурированная запись о том, что именно произошло, когда и в каком контексте.
    * Они помогают расследовать конкретные инциденты, восстановить цепочку действий пользователя или найти причину ошибки.
* **Метрики** это агрегированные числовые значения во времени.
    * Это числа, измеряемые через регулярные интервалы во времени
    * **Пример:** CPU usage = 45%, Memory = 512MB, ...
    * Они нужны для визуализации общего состояния системы на дашбордах, понимания трендов и быстрого реагирования на аномалии.
### 2. Структурированное логирование
* В продакшене нельзя писать логи в обычный текст потому что логи могут стать огромными и занимать очень много места, а системы аналитики будут использовать тяжелые регулярные выражения чтобы вытащить какие-то данные пользователя.
* **Как работает JSON-формат:**
    * **Мгновенный поиск:** Системы сбора логов автоматически распарсяи JSON и индексируют каждое поле.
    * **Точные фильтры:** В специальных ПО можно просто одним кликом искать данные по условиям.
* **Уровни логирования:**
    1. **DEBUG:** Детальная иформация для отладки во время разработки (значения переменных, шаги алгоритма)
    2. **INFO:** Подтверждение того, что всё идет по плану
    3. **WARNING:** Случилось что-то неожиданное, но приложение продолжает работать (повторная попытка соединения с внешним API).
    4. **ERROR:** Произошла серьёзная ошибка, из-за которой конкретная операция/запрос не выполнился.
    5. **CRITICAL/FATAL:** Авария. Приложение или его ключевой компонент полностью вышли из строя и не могут продолжать работу.
### 3. Алертинг на основе логов
* Системы мониторинга непрерывно анализируют логи:
    1. Приложение пишет JSON-логи в stdout
    2. Облачный агент считывает поток логов и отправляет в хранилище
    3. Система мониторинга отслеживает правила, например: Если количество логов ERROR превышает 20 штук за 1 минуту - создать инцидент.
    4. Система отправляет уведомление через Webhook в Telegram.
