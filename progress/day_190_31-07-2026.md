# День 190 (31.07.2026): Мокирование (Mocking), Изоляция и pytest-mock
## Теория:
* Зачем нужно мокирование: изоляция юнит-тестов от внешнего мира (третьих API, платежных шлюзов, отправки Email, работы с диском и реальной БД).
* Анатомия Mock-объектов: отличие Mock от MagicMock, переопределение возвращаемых значений (return_value) и симуляция ошибок (side_effect).
* Плагин pytest-mock: использование фикстуры mocker вместо громоздкого стандартного декоратора unittest.mock.patch.
* Проверка взаимодействия: методы assertion моков (assert_called_once(), assert_called_with(...)) для проверки того, что ваш код действительно вызвал внешний сервис с правильными аргументами.
* Фикстура monkeypatch: встроенный инструмент pytest для безопасного временного изменения переменных окружения (envvars), словарей и атрибутов модулей на время теста.
## Практика:
* Установи плагин pytest-mock: pip install pytest-mock.
* Возьми функцию, которая делает реальный HTTP-запрос к стороннему API (например, погода или курсы валют через requests / httpx), и замокай сетевой вызов с помощью mocker.patch.
* Напиши тест для метода оплаты: подмени вызов Stripe/Paypal так, чтобы он возвращал статус {"success": True}, и проверь через assert_called_once_with, что сумма платежа передана верно.
* С помощью фикстуры monkeypatch переопредели переменную окружения SECRET_KEY во время выполнения одного конкретного теста.

## Конспект изученных материалов
### 1. Зачем нужно мокирование
* **Своими словами:** mocking (заглушка) нужна для того чтобы ограничить функциям обращение в внешнему миру. Причины по которым это делается:
    1. **Скорость:** Пока тесты будут обращаться в внешним API будут проходить секунды, но тесты должны выполняться за миллисекунды
    2. **Надежность:** Если сторонний сервис к которым будут обращаться тесты упал, значит тесты тоже упадут
    3. **Безопасность:** Никто бы не хотел чтобы за каждые тесты тратились их токены или же с их карт снимались реальные деньги просто чтобы протестировать, или же рассылать сотни писем по SMTP пользователям своего сервиса.
### 2. Анатомия Mock-объектов
* Для подмены реальных объектов используются моки. И важно понимать отличие обычных моков от магических моков, а также переопределение возвращаемых значений и симуляции ошибок
    * **Mock:** используется для подмены обычных функций или методов
    * **MagicMock:** используется если нужно замокать объект который используется в цикле или функций len.
* **Управление поведением мока:**
    * *return_value:* Указывает моку какой ответ он должен вернуть (Например JSON ответ)
    * *side_effect:* Позволяет симулировать сложные поведения. С его помощью можно выбросить исключение или возвращать разные значения при каждом новом вызове.
### 3. Плагин pytest-mock
* Плагин pytest-mock позволяет использовать удобную фикстуру mocker вместо громоздкого стандартного декоратора unittest.mock.patch. Это делает код чище и полностью вписывается в экосистему фикстур pytest.
