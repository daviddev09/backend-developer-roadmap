## Конспект изученных материалов
### 1. Как передавать переменные окружения в Docker контейнеры
* Чтобы передавать переменные окружения в изолированные Docker контейнеры нужно при запуске: *docker run -d -e APP_ENV=production my-python-app* передать таким образом. Это идеально подходит для передачи 1-2 несекретных параметров. Не подходит если 20 переменных, тогда команда станет нечитаемой. Главный минус это то что эти команды сохраняются в истории bash. Любой кто получит доступ к серверу, сможет прочитать пароли просто посмотрев историю команд.
### 2. Инструкция env_file в docker-compose
* Чтобы не писать длинные команды с десятками флагов **-e**, придумали передачу целого файла. Вместо того чтобы жестко прописывать пароли в блоке environment внутри docker-compose.yml, мы указываем Docker Compose прочитать файл .env и загрузить все его содержимое в контейнер. И когда запускается: *docker compose up -d*, Docker сам найдет файл .env, прочитает его и вольет переменные внутри контейнеров где был объявлен env_file: -.env
### 3. Интеграция с CI/CD
* Системы CI/CD запускают код у себя на своих облачных серверах и так как строго запрещается пушить .env файлы в репозиторий, они могут получить эти секретные данные только с одного места: из механизма Secrets.
