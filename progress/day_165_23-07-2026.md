# День 165 (23.07.2026): Знакомство с Docker. Образы и Контейнеры
## Теория:
* Концепция контейнеризации: в чем принципиальное отличие Docker-контейнеров от классических виртуальных машин (меньше вес, быстрее запуск, использование общего ядра ОС).
* Понятие Образа (Image): это неизменяемый шаблон или "чертеж" приложения со всеми нужными библиотеками.
* Понятие Контейнера (Container): это запущенный экземпляр образа, изолированная среда, в которой работает программа.
* Docker Hub: официальный реестр, откуда скачиваются готовые образы (например, официальные образы Ubuntu, Python, Nginx, PostgreSQL).
* Жизненный цикл контейнера: запуск (docker run), просмотр активных (docker ps), просмотр всех вообще (docker ps -a), остановка (docker stop), удаление контейнера (docker rm) и удаление образа (docker rmi).
## Практика:
* Установи Docker на свою виртуальную машину Ubuntu Server или локальный компьютер.
* Скачай и запусти тестовый образ командой docker run hello-world и прочитай приветственное сообщение в консоли.
* Запусти полноценный веб-сервер в фоновом режиме: docker run -d nginx.
* Проверь список запущенных контейнеров командой docker ps и найди сгенерированное имя твоего контейнера Nginx.
* Останови этот контейнер командой docker stop <имя_или_id> и удали его через docker rm <имя_или_id>.

## Конспект изученных материалов
### 1. Концепция контейнеризации
* При разработке ПО часто может возникать пробелма: Разработчик пишет код на своем ноутбуке и у него всё работает но когда кто-то запускает его код у себя на ПК, код падает с ошибкой, и это из-за несоответствия версий. Это и создает проблему: **А у меня всё работало!**
* **Виртальная машина:** создает эмуляцию физического железа. Внутри него устанавливается полноценная операционная система со своим собственным ядром Linux/Windows, системными службами и процессами. **Минусы ВМ:**
    * Огромный вес
    * Медленный запуск
    * Высокое потребление ресурсов
* **Docker: Контейнеризация:** Все контейнеры на машине работают поверх единого общего ядра хостовой операционной системы. Контейнеру не нужно загружать операционную систему, запускать systemd, запускать драйверы, эмулировать оборудование. **Из-за этого контейнер:**
    * весит намного меньше
    * запускается за секунды
    * использует меньше памяти
### 2. Понятие образа (Docker Image)
* **Image** - это неизменяемый шаблон, из которого содаются контейнеры. Образ неизменяем, можно создать новый, но не изменить. Можно представить его как чертёж. Он содержит:
    * Linux
    * Python
    * Postgres
    * Redis
    * библиотеки
    * приложение
    * настройки
    * НО, ничего не выполняет
### 3. Понятие контейнера
* **Контейнер (Container)** - это запущенный экземпляр образа. Это изолированный процесс на компьютере. Можно представить образ как класс в ООП, а контейнер как объект класса. Из одного и того же образа можно запустить много совершенно независимых контейнеров
### 4. Docker Hub
* **Docker Hub (hub.docker.com)** - это публичное хранилище готовых Docker-образов (аналог GitHub). Там хранятся официальные образы, оптимизированные и проверенные разработчиками
### 5. Жизненный цикл контейнера
1. **Запуск контейнера:** *docker run*. Она выполняет сразу три действия:
    * Ищет образ локально. Если его нет - скачивает с Docker Hub
    * Создает контейнер (docker create)
    * Запускает его (docker start)
    * **Синтаксис:** *docker run <флаги> <имя образа:тег> <команда>
2. **Главные флаги docker run:**
    * **-d** (detached): Запустить контейнер в фоновом режиме (в демоне)
    * **--name**: дать контейнеру понятное имя
    * **-p <порт хоста>:<порт контейнера>**: пробросить с ПК внутрь контейнера
    * **-it**: -i(interactive) + -t (tty) - запустить в интерактивном режиме с доступом к терминалу.
    * **--rm**: автоматически удалить контейнер с диска после его остановки
    * **-e <KEY=VALUE>**: передать переменную окружения внутри контейнера
### Docker команды
1. Команды запуска:
    * *docker run -d --name my-web-server -p 8080:80 nginx* - запустить контейнер в фоновом режиме, присвоить имя и связать порт 8080 с портом ОС внутри контейнера 80.
    * *docker run -it --rm ubuntu bash* - интерактивный запуск Ubuntu
2. Просмотр контейнеров
    * *docker ps* - показать запущенные контейнеры
    * *docker ps -a* - показать все контейнеры включая остановленные, завершившееся с ошибкой и т.д.
3. Остановка и повторный запуск
    * *docker stop my-web-server* - мягкая остановка (отпарвляет сигнал SIGTERM, давая контейнеру время на сохранение данных)
    * *docker start my-web-server* - запуск уже остановленного контейнера
    * *docker kill my-web-server* - принудительная остановка (сигнал SIGKILL)
4. Удаление контейнера
    * Нельзя удалить работающий контейнер без флага -f. Сначала нужно его остановить (без влага -f если)
    * *docker rm my-web-server* - удаление контейнера из системы
    * *docker rm -f my-web-server* - удаление работающего контейнера (принудительно)
    * *docker container prune* - разом очистить все остановленные контейнеры
5. Просмотр и удаление образов
    * *docker images* - показать список всех скачанных образов
    * *docker rmi nginx* - удалить конкретный образ
    * *docker rmi -f nginx* - принудительно удалить образ 
    * *docker image prune -a* - удалить все неиспользуемые образы
