## Конспект изученных материалов
### 1. Стандартные потоки ввода/вывода
* В философии Linux всё есть файл. Даже когда программа выводит текст на экран, она на самом деле "пишет" в специальный системный файл. У каждой программы по умолчанию есть три потока
    * **stdin (Standard Input, поток 0):** То, что программа получает на вход (по умолчанию нажатия клавиш с клавиатуры)
    * **stdout (Standard Output, поток 1):** Успешный результат работы программы. По умолчанию выводится на экран терминала.
    * **stderr (Standard Error, поток 2):** Сообщения об ошибках. Тоже по умолчанию выводятся на экран, но система отличает их от обычного вывода
* **Перенаправление вывода (> и >>)** Вместо того чтобы выводить текст на экран, мы можем "перенаправить" его прямо в файл.
    * **> (Одинарная стрелка) - Перезапись:** Записывает вывод в файл. Если файл уже существовал, его старое содержимое будет полностью стерто: *echo "Hello, David!" > daviddev.txt*
    * **>> (Двойная стрелка) - Добавление:** Добавляет текст в конец существующего файла, сохраняя всё, что там было до этого: *echo "Это вторая строка." >> daviddev.txt*
    * Если файла не существует, обе команды создадут его автоматически.
### 2. Мощь пайпов (Pipes: |)
* Символ | (от английского pipe - труба) это фундамент автоматизации в Linux. Пайп берет stdout слева и передает как stdin команде справа.
* **Пример:** Представь папку, в которой 1000 файлов. Если ты введешь *ls -la*, терминал выплюнет весь список, и ты увидишь только конец. Соединим *ls* с утилитой чтения *less*:
    * *ls -la | less*
    * **Как это работает:** ls собирает список файлов, но не кидает их на экран, а "сливает по трубе" в программу less. Теперь ты можешь спокойно листать стрелочками
### 3. Поиск файлов: **find**
* Команда find - это мощнейший поисковик по файловой системе. В отличие от Windows, где поиск может занять несколько минут, find работает очень быстро.
* **Синтаксис:** *find <где искать> <критерии поиска>*
* Поиск по имени (-name):
    * *find ~ -name "report.txt"* Найти файл report.txt в домашней директории
    * *find . -name "*.log" Использовать звездочку для поиска всех файлов с расширением .log
* Поиск без учета регистра (-iname):
    * *find /var/log -iname "SysLOg"*
* Поиск по типу (-type):
    * *find ./my_project -type d* Иногда нужно найти только папки (d-directory) или только файлы (f-file)
* Поиск по размеру (-size):
    * *find f -size +100M* Искать файлы больше 100 Мегабайт. Можно искать как файлы больше (+) так и меньше (-) определенного размера
### 4. Поиск текста внутри файлов: **grep**
* Если find ищет сами файлы, то grep (Global Regular Expression Print) ищет текст внутри файлов. Синтаксис: *grep <флаги> <что ищем> <где ищем>*:
    * *grep "failed" /var/log/auth.log* Базовый поиск
    *  *grep -i "error" /var/log/syslog* Игнорирование регистра (-i). По умолчанию grep чувствителен к регистру. Флаг -i отключает это
    * *grep -r "password" /etc/* Рекурсивный поиск по всем файлам в папке (-r). 
### 5. Высший пилотаж: Чтение логов с помощью пайпов.
1) **Отфильтровать историю команд:** Ты помнишь, что вчера вводил длинную команду с docker, но забыл её точный синтаксис. Команда history выводит историю всего терминала:
    * *history | grep "docker"* (Берем всю историю -> передаем в grep -> grep выводит только строки со словом "docker")
2) **Поиск ошибок в логах "на лету":** Если лог летит слишком быстро, можно отфильтровать только ошибки:
    * *tail -f /var/log/syslog | grep -i "error"* (Теперь терминал будет висеть в ожидании, и как только в системе произойдет событие со словом error или Error, оно появится на экране)
3) **Сбор всех ошибок в отдельный файл:** Допустим, ты хочешь собрать все логи о неудачных входах в систему:
    * *cat /var/log/auth.log | grep -i "failed" > /home/user/failed_logins.txt* (Прочитать весь лог -> оставить только строки с "failed" -> сохранить результат в новыйы текстовый файл)
