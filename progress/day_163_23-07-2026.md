# День 163 (23.07.2026): Системные службы (Systemd и Systemctl)
## Теория:
* Что такое демоны (daemons) и фоновые системные службы.
* Введение в systemd — современную систему инициализации в Linux, управляющую службами.
* Работа с утилитой systemctl: запуск (start), остановка (stop) и перезагрузка конфигураций (restart, reload) служб.
* Просмотр статуса службы: systemctl status <имя_службы>.
* Автозагрузка при старте системы: команды enable и disable.
* Централизованное управление логами: как читать журналы конкретной службы с помощью утилиты journalctl (флаги -u для указания службы и -f для слежения в реальном времени).
## Практика:
* Проверь статус службы планировщика задач (обычно это cron или cron.service) с помощью systemctl status cron.
* Попробуй остановить службу командой sudo systemctl stop cron (потребуются права администратора). Проверь статус снова.
* Запусти службу обратно с помощью sudo systemctl start cron.
* Открой логи этой службы за сегодняшний день с помощью команды journalctl -u cron --since today

## Конспект изученных материалов
### 1. Что такое Демоны
* **Демон (Daemon)** - это фоновый процесс в Unix/Linux, который работает без прямого участия пользователя и не привязан к конкретному терминалу. Демоны запускаются при старте системы и уходят в спящий режим, просыпаясь только тогда, когда появляется работа.
* **Как их узнать?** По традиции имена программ-демонов заканчиваются на букву d:
    * **sshd** демон Secure Shell (принимает ssh-подключения)
    * **httpd/named/ftpd** демоны веб сервера, DNS и FTP
    * **systemd** главный системный демон
    * **crond** демон планировщика задач
### 2. Введение в systemd
* **systemd** это система инициализации и менеджер системных служб.
* Когда ядро Linux завершает инициализацию железа, оно запускает самый первый процесс в операционной системе м PID 1.
* **Концепция Юнитов (Units):** В systemd всё управляется через юниты (файлы конфигураций). Существует несколько  типов юнитов, но основные из них:
    * **.service** системные службы
    * **.socket** сетевые сокеты (позволяют откладывать запуск до первого прихода запроса)
    * **.timer** таймеры
    * **.target** группы юнитов
### 3. Утилита systemctl
* **systemctl** эта утилита Главный интсрумент для взаимодействия с systemd. Для изменения состояний служб требуются права суперпользователя (sudo). Базовые команды управления:
    * *sudo systemctl start cron* - запустить службу
    * *sudo systemctl stop cron* - остановить службу
    * *sudo systemctl restart nginx* - полностью очищает службу, очищает память, полностью останавливает и заново запускает процесс
    * *sudo systemctl reload nginx* - перезагружает конфигурацию без остановки процесса. Применяет новые файлы настроек без обрыва соединений с клиентом.
### 4. Просмотр статуса службы
* Чтобы узнать что происходит со службой прямо сейчас, используется команда **status**: *systemctl status cron*
### 5.  Управление автозагрузкой
* *sudo systemctl enable <имя файла>* - включить автозагрузку
* *sudo systemctl disable <иия файла>* - выключить автозагрузку
* *sudo systemctl enable --now <имя файла>* - включить автозагрузку и запустить службу
### 6. Централизованные логи
* В systemd за логирование отвечает отдельный демон - systemd-journald. Он собирает выводы абсолютно всех служб и ядра в единую бинарную базу данных. Для чтения этой базы используется утилита **journalctl**:
    * *journalctl -u cron* - посмотреть логи конкретной службы (флаг -u от 'unit')
    * *journalctl -u nginx -f* - мониторинг логов в реальном времени
    * *journalctl -u cron -n 20* - Показать только последний N строк
    * **Фильтрация логов по времени:**
        * *journalctl -u cron --since today*
        * *journalctl -u cron --since "2026-07-23 00:00:00"*
        * *journalctl -u cron --since "1 hour ago"*
    * *journalctl -b* - Посмотреть логи только за текущую загрухку системы
