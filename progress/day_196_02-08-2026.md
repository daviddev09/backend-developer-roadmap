# День 196 (02.08.2026): Мокирование сторонних сервисов на уровне API
## Теория:
* Границы интеграционного тестирования: почему при тестировании API не нужно отправлять реальные письма, списывать деньги с тестовых карт Stripe или дергать реальный AWS S3.
* Подмена зависимостей на уровне веб-фреймворка: использование механизмов вроде app.dependency_overrides в FastAPI для замены реальных сервисов на классы-заглушки.
* Библиотеки Responses / VCR.py / httpx-mock: как перехватывать исходящие HTTP-запросы из твоего кода на уровне сети и отдавать заранее подготовленные JSON-ответы.
## Практика:
* Выбери или создай эндпоинт, который выполняет внешнее действие (например, POST /api/checkout — отправляет запрос в платежный шлюз).
* Используй pytest-mock (mocker.patch) или dependency_overrides, чтобы подменить класс оплаты на Mock-объект, возвращающий успешный статус транзакции.
* Напиши тест, который дергает эндпоинт checkout и проверяет две вещи: API вернуло пользователю статус 200, а в БД статус заказа изменился на "Оплачен" (несмотря на то, что реальный платеж не проходил).
* Проверь через метод мока assert_called_once_with, что твой API передал во внешний сервис правильную сумму и ID заказа.

## Конспект изученных материалов
### 1. Границы интеграционного тестирования
* Интеграционные тесты проверяют как компоненты API работают друг с другом, но в его зону ответственности не входит проверка работоспособности серверов.
