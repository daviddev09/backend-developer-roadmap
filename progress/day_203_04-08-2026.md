# День 203 (04.08.2026): Введение в Redis и базы данных In-Memory
## Теория:
* Что такое Redis: почему базы данных в оперативной памяти (In-Memory) работают в сотни раз быстрее традиционных реляционных БД на жестких дисках. Разница между постоянным хранилищем (PostgreSQL) и временным (Redis).
* Архитектура Key-Value (Ключ-Значение): базовая концепция хранения данных, где каждому уникальному ключу соответствует определенное значение.
* Базовые типы данных Redis: строки (Strings), списки (Lists), множества (Sets) и хеши (Hashes). Почему Redis — это не просто "хранилище строк", а сервер структур данных.
* Жизненный цикл ключа (TTL - Time to Live): концепция автоматического удаления данных по истечении заданного времени, что делает Redis идеальным для сессий и временных кодов.
## Практика:
* Установи Redis локально или запусти его через Docker: docker run --name my-redis -p 6379:6379 -d redis.
* Подключись к серверу через терминал с помощью встроенной утилиты: redis-cli.
* Выполни базовые команды прямо в консоли: создай ключ (SET user:1 "John"), прочитай его (GET user:1), установи время жизни на 10 секунд (EXPIRE user:1 10) и проверь остаток времени (TTL user:1).
* Установи библиотеку для Python: pip install redis. Напиши простейший скрипт, который подключается к локальному Redis, записывает строку и читает её обратно.

## Конспект изученных материалов
### 1. Что такое Redis
* **Redis (Remote Dictionary Server)** — это высокопроизводительная база данных типа «ключ-значение», хранящая все данные непосредственно в оперативной памяти (RAM), а не на жестком диске (SSD/HDD).
* **Разница между дисковыми и In-Memory БД:**
    * **Классические БД (PostgreSQL):** Когда приходит запрос, СУБД должна считать данные с жесткого диска или SSD.Главная цель PostgreSQL — надежность и долговечность (Persistence). Если отключить электричество, данные останутся на диске.
    * **In-Memory БД (Redis):** Все данные живут в RAM. Задержка доступа к оперативной памяти измеряется наносекундами (в сотни и тысячи раз быстрее SSD).
    * **Однопоточная архитектура (Single-threaded Event Loop):** Redis обрабатывает запросы последовательно в одном основном потоке через цикл событий. Это избавляет его от накладных расходов на переключение контекста процессора и блокировки (locks) при параллельном доступе. Все операции в Redis выполняются атомарно.
### 2. Архитектура Key-Value
* **Своими словами:** В отличии от СУБД (Например Postgres) где данные хранятся в таблицах, Redis хранит данные в виде уникальных хэшей с своими значениями. В Redis хэщи уникальны и поисе по ним состовляет $O(1)$ - мгоновенный поиск, независимо от того лежит там 10 записей или 10 миллионов
### 3. Базовые типы данных в Redis
* **Строки (Strings):** Самый базовый тип. Могут хранить текст, JSON, бинарные данные (до 512 МБ) или числа. На числах в строках можно выполнять атомарные операции инкремента.
    * Применение: Кэш HTML-страниц, токены сессий, счетчики просмотров.
* **Списки (Lists):** Связанные списки строк. Позволяют мгновенно ($O(1)$) добавлять элементы в начало (LPUSH) или в конец (RPUSH), а также извлекать их (LPOP, RPOP).
    * Применение: Простейшие очереди задач, ленты последних новостей, история действий.
* **Множества (Sets):** Неупорядоченные коллекции уникальных строк. Повторные элементы игнорируются. Поддерживают операции пересечения (SINTER) и объединения множеств.
    * Применение: Теги статей, уникальные посетители (IP), списки друзей, онлайн-пользователи.
* **Хеши (Hashes):** Это словари внутри словарей (field: value). Идеально подходят для представления объектов без необходимости сериализации всего объекта в JSON.
    * Применение: Профили пользователей, настройки, корзина покупок.
### 4. Жизненный цикл ключа (TTL — Time to Live)
* Одна из главных фич Redis — возможность задать ключу время жизни (TTL). По истечении этого времени Redis автоматически удалит ключ из памяти без вмешательства твоего кода.
* **Зачем нужен TTL:**
    * Самоочистка кэша: Чтобы оперативная память не переполнялась.
    * Одноразовые пароли (OTP): SMS-код для входа, который действителен 3 минуты.
    * Ограничение запросов (Rate Limiting): Заблокировать IP на 15 минут при частых попытках входа.
    * Сессии: Токен авторизации, автоматически сгорающий через 7 дней.
